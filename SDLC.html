Planning & Requirements Analysis

April 2026 — Initial Planning

Project Overview

AstraNotes is a secure, multi-user note-taking web application with client-side encryption. Users register/login with username/password, and note bodies are encrypted in the browser (PBKDF2 + AES-GCM) before being stored on the server as opaque ciphertext.

React 19 + Vite 6 (SPA)
Express + better-sqlite3 (API)
Web Crypto API (Encryption)
SQLite (Persistence)

Testing & Quality Assurance

Ongoing — Vitest + Supertest

Testing Strategy

Client Tests (jsdom)

Vitest with jsdom environment. Setup: src/test/setup.ts loads fake-indexeddb/auto + @testing-library/jest-dom/vitest.

  • Crypto vault tests
  • Tag normalization tests
  • Delete confirm preference tests
  • Note search tests

Server Tests (node)

server/app.test.ts — Supertest with request.agent(app), temp DB in os.tmpdir().

  • Register + login flow
  • Cross-user PUT forbidden (403)
  • Assert ciphertext in DB responses (not plaintext)
  • Encrypted save/list with v2 payload

Quality Commands

  • npm run test — Vitest run
  • npm run test:watch — Vitest watch
  • npm run lint — ESLint (excludes server/)
  • npm run typecheck — TSC both configs
  • npm run build — Typecheck + Vite build

Test config: vite.config.ts with environmentMatchGlobs for server tests → node.

Security Testing Focus

Key Security Test Patterns

  • Sec 1 API tests assert ciphertext in DB responses, not plaintext titles
  • FR6-S Cross-user access returns 403; second scenario with user B attempting user A's note
  • FR1 Autosave with vault open/closed branches; lastSavedAt on 204, ErrorBanner on failure
  • Sec 1 Decrypt failure uses AN_CRYPTO_003 with explicit user message
  • Sec 3 API sets Cache-Control: no-store on /api/* routes

Deployment & Maintenance

April 2026 — Docker, Dev Container, Operations

Deployment Architecture

Development (Local)

npm run dev — Concurrently runs API (:3001) + Vite (:5173)

  • Vite proxies /api → http://127.0.0.1:3001
  • Hot reload for both client and server
  • SQLite at ./data/astranotes.db

Docker Development

Docker Compose with bind-mounts for live editing inside Linux container.

  • npm run docker:up — dev profile
  • node_modules as named volume (Linux binaries)
  • ./data mounted for SQLite persistence

Production Docker

Express serves SPA + API on port 4173 (no Vite preview).

  • npm run docker:prod — profile prod
  • SESSION_SECRET required in production
  • Serves dist/ and /api on single port

Dev Container

Cursor/VS Code Dev Container using same Compose service.

  • .devcontainer/devcontainer.json
  • Consistent Linux environment
  • Cross-platform (Mac, Windows, Linux)

Operational Considerations

Security Constraints

Sec 1 Non-localhost HTTP breaks crypto.subtle — use HTTPS via reverse proxy (Caddy, Nginx, Tailscale).

README.md — Troubleshooting

SQLite Journal Mode

WAL auto-selected on local disks; falls back to DELETE on network filesystems. Configurable via ASTRANOTES_SQLITE_JOURNAL_MODE.

server/db.ts, .env.example

Native Dependencies

better-sqlite3 requires platform-specific binaries. Never copy node_modules between OSes. Use npm rebuild better-sqlite3 on Windows if needed.

README.md — Cross-platform

Environment Configuration

SESSION_SECRET (required prod), PORT (default 3001), ASTRANOTES_DB_PATH (optional). Copy .env.example to .env to override.
